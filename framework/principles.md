# Core Principles

These eight principles summarize the intent behind the Ballast controls. Each principle lists the controls that implement it.

| # | Principle | What it means | Implemented by |
|---|---|---|---|
| 1 | **Know what you run, and where it came from** | Every AI asset, including AI features embedded in SaaS and pilots on real data, is registered with a named owner and a risk rating before it reaches production users or data, and everything the organization builds has a current record of the models, tools and data sources it depends on. | [BAL-1.4](../controls/control-catalog.md#bal-1-4), [BAL-1.5](../controls/control-catalog.md#bal-1-5), [BAL-1.6](../controls/control-catalog.md#bal-1-6), [BAL-1.7](../controls/control-catalog.md#bal-1-7), [BAL-8.7](../controls/control-catalog.md#bal-8-7) ([T2](../guides/tiering.md#t2): [BAL-4.13](../controls/control-catalog.md#bal-4-13), [BAL-5.15](../controls/control-catalog.md#bal-5-15)) |
| 2 | **Agents are identities** | Each agent that acts with its own credentials has its own scoped identity, its credentials are kept out of model context and expire, and every delegated action carries both the user and the agent so it can be traced to an accountable person. | [BAL-2.1](../controls/control-catalog.md#bal-2-1), [BAL-2.3](../controls/control-catalog.md#bal-2-3), [BAL-2.4](../controls/control-catalog.md#bal-2-4) ([T2](../guides/tiering.md#t2): [BAL-2.10](../controls/control-catalog.md#bal-2-10), [BAL-2.11](../controls/control-catalog.md#bal-2-11), [BAL-2.12](../controls/control-catalog.md#bal-2-12); [T3](../guides/tiering.md#t3): [BAL-2.13](../controls/control-catalog.md#bal-2-13)) |
| 3 | **Least agency, [earned autonomy](../guides/tiering.md#autonomy-levels)** | [Autonomy](../guides/tiering.md#autonomy-levels) is recorded per action class and enforced outside the model, agents hold only the tools and scopes their task needs, high-risk actions need human approval, either per action or within the limits and expiry approved for [A3](../guides/tiering.md#a3), and moving up an [autonomy level](../guides/tiering.md#autonomy-levels) requires evidence at a promotion gate. | [BAL-3.1](../controls/control-catalog.md#bal-3-1), [BAL-3.2](../controls/control-catalog.md#bal-3-2), [BAL-3.4](../controls/control-catalog.md#bal-3-4), [BAL-3.6](../controls/control-catalog.md#bal-3-6) ([T2](../guides/tiering.md#t2): [BAL-3.10](../controls/control-catalog.md#bal-3-10), [BAL-3.12](../controls/control-catalog.md#bal-3-12), [BAL-3.13](../controls/control-catalog.md#bal-3-13)) |
| 4 | **Untrusted content never grants authority** | Content the user did not author is handled as data; it cannot grant tools, permissions or identity, and its presence narrows what an agent may do without a deterministic check or a human. | [BAL-3.5](../controls/control-catalog.md#bal-3-5), [BAL-6.1](../controls/control-catalog.md#bal-6-1), [BAL-6.2](../controls/control-catalog.md#bal-6-2), [BAL-6.3](../controls/control-catalog.md#bal-6-3) ([T2](../guides/tiering.md#t2): [BAL-6.21](../controls/control-catalog.md#bal-6-21); [T3](../guides/tiering.md#t3): [BAL-6.22](../controls/control-catalog.md#bal-6-22)) |
| 5 | **Protections follow the data** | Classification and access rules are enforced wherever AI touches data: in what is retrieved for each requester, in what is written to memory, and in what the model's output discloses. | [BAL-4.1](../controls/control-catalog.md#bal-4-1), [BAL-4.7](../controls/control-catalog.md#bal-4-7), [BAL-4.10](../controls/control-catalog.md#bal-4-10), [BAL-4.11](../controls/control-catalog.md#bal-4-11) ([T2](../guides/tiering.md#t2): [BAL-4.2](../controls/control-catalog.md#bal-4-2), [BAL-4.15](../controls/control-catalog.md#bal-4-15)) |
| 6 | **Test like an attacker, on every change** | Every change to a model, prompt, tool or data source is re-tested against direct and indirect prompt injection, tool misuse and exfiltration, and results outside defined thresholds block release. | [BAL-5.3](../controls/control-catalog.md#bal-5-3), [BAL-5.4](../controls/control-catalog.md#bal-5-4), [BAL-5.5](../controls/control-catalog.md#bal-5-5), [BAL-5.6](../controls/control-catalog.md#bal-5-6) ([T2](../guides/tiering.md#t2): [BAL-5.7](../controls/control-catalog.md#bal-5-7), [BAL-5.8](../controls/control-catalog.md#bal-5-8), [BAL-5.9](../controls/control-catalog.md#bal-5-9), [BAL-5.11](../controls/control-catalog.md#bal-5-11)) |
| 7 | **Every action attributable, every policy decision explained** | Every agent action is recorded by the enforcement point rather than reported by the agent, with the user, agent, tool, target and the policy decision that allowed or blocked it, and prompt logs are protected as the sensitive records they are. | [BAL-7.1](../controls/control-catalog.md#bal-7-1), [BAL-7.2](../controls/control-catalog.md#bal-7-2) ([T2](../guides/tiering.md#t2): [BAL-7.8](../controls/control-catalog.md#bal-7-8), [BAL-7.9](../controls/control-catalog.md#bal-7-9), [BAL-7.10](../controls/control-catalog.md#bal-7-10), [BAL-7.11](../controls/control-catalog.md#bal-7-11)) |
| 8 | **Contain first: a tested off-switch and a small blast radius** | An authorized operator can halt an agent within a defined time using an off-switch that is tested, and execution limits, isolation and default-deny egress keep the damage a misbehaving agent can do small. | [BAL-3.7](../controls/control-catalog.md#bal-3-7), [BAL-6.12](../controls/control-catalog.md#bal-6-12), [BAL-6.13](../controls/control-catalog.md#bal-6-13), [BAL-6.14](../controls/control-catalog.md#bal-6-14), [BAL-7.4](../controls/control-catalog.md#bal-7-4) ([T2](../guides/tiering.md#t2): [BAL-3.11](../controls/control-catalog.md#bal-3-11), [BAL-7.5](../controls/control-catalog.md#bal-7-5)) |

**How to read the table.** Controls outside the brackets are [T1](../guides/tiering.md#t1). Controls marked [T2](../guides/tiering.md#t2) add protection for assets rated High or Critical, and [T3](../guides/tiering.md#t3) controls are required only where an action class runs at [autonomy level](../guides/tiering.md#autonomy-levels) [A4](../guides/tiering.md#a4). Each control applies according to its capability tags, so not every listed control applies to every asset; for example [BAL-6.13](../controls/control-catalog.md#bal-6-13) applies only to assets tagged EXEC: code, shell commands or model-directed filesystem writes, subject to the controlled-export rule. [BAL-6.4](../controls/control-catalog.md#bal-6-4) (prompt injection detection and response) supports principle 4 as detection telemetry only. Detection is a tripwire, not a boundary, so it is not listed as an implementing control.

## Two directions: principles 3 and 4

Agent security has to work in two directions: protect our agents from the world, and protect ourselves from our agents. Principle 4 covers the first direction. Email, shared documents, web pages, tool results and messages from other agents can all carry instructions an attacker wrote, so that content is treated as data and cannot hand out tools, permissions or identity. Principle 3 covers the second. Even an agent working as intended, or one manipulated despite principle 4, can do only what its [autonomy level](../guides/tiering.md#autonomy-levels), tools and scopes allow, and high-risk actions need human approval, either per action or within the limits and expiry approved for [A3](../guides/tiering.md#a3).

Do not rely on the model alone to distinguish trusted instructions from untrusted content. Enforce permissions and trust boundaries outside the model. [BAL-3.5](../controls/control-catalog.md#bal-3-5), often called the Rule of Two, joins them: within one session an agent does not combine content an attacker can influence, access to sensitive data or systems, and a channel that changes state or leaves the trust boundary, unless each outbound or state-changing action passes a deterministic control or human approval. When both principles fail, principle 8 limits the damage.
