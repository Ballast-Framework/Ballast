# Domain 7: Observability, Detection & Response

**Objective:** Make every AI action attributable and every AI security signal actionable, so the organization can detect misuse, reconstruct what happened from records the agent cannot alter, and contain and recover from AI incidents.

## Why it matters

Agents act at machine speed with real credentials, so the record of what they did must come from the systems that executed each action, not from the model's own account. Attacks through AI integrations also look like legitimate use. In the Salesloft Drift breach (August 2025), attackers used stolen OAuth tokens from an AI chat agent's Salesforce integration to bulk-export data from many customer tenants, and Google's threat intelligence team advised treating every Drift-connected token as compromised. Detection without response also fails. In ShareLeak (Copilot Studio, CVE-2026-21520, since patched), a safety classifier flagged the injected payload and customer data left anyway. This domain makes AI telemetry trustworthy and complete, routes AI signals to an owner, and adds the revocation, evidence-preservation and rollback steps that general incident plans lack.

**Key risks addressed**

- [OWASP Top 10 for LLM Applications 2026](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/README.md): LLM01:2026 Prompt Injection; LLM02:2026 Sensitive Information Disclosure; LLM03:2026 Excessive Agency
- [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/): ASI02 Tool Misuse & Exploitation; ASI03 Identity & Privilege Abuse; ASI08 Cascading Failures; ASI10 Rogue Agents
- [MITRE ATLAS](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.09) (release 2026.09): AML.T0086 Exfiltration via AI Agent Tool Invocation; AML.T0077 LLM Response Rendering; AML.T0085 Data from AI Services; AML.T0081 Modify AI Agent Configuration

Control-level references to OWASP, [MITRE ATLAS](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.09), [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) and [ISO/IEC 42001](https://www.iso.org/standard/42001): [Standards crosswalk](../../mappings/crosswalk.md#domain-7)

## What 'detected' means

Across Ballast, a control that requires something to be detected is met only when the detection produces an alert that reaches an accountable owner and is handled under a defined response. [BAL-7.3](../../controls/control-catalog.md#bal-7-3) supplies the owner, severity and triage runbook for each AI security event type, and [BAL-7.4](../../controls/control-catalog.md#bal-7-4) supplies the response for AI incident types. A detection that is only written to a log, or that reaches no one with authority to act, does not count. An alert closed by an AI agent counts as handled only under the sampling and self-closure rules in [BAL-7.3](../../controls/control-catalog.md#bal-7-3). Detection adds to prevention but does not replace it: where a control requires a deterministic limit (for example [BAL-3.5](../../controls/control-catalog.md#bal-3-5) or [BAL-6.1](../../controls/control-catalog.md#bal-6-1)), a detector does not satisfy it.

## Which record is which

| Record | Controls | Written by | Holds prompt content? |
|---|---|---|---|
| Agent action log | [BAL-7.1](../../controls/control-catalog.md#bal-7-1) ([T1](../../guides/tiering.md#t1)); [BAL-7.11](../../controls/control-catalog.md#bal-7-11) ([T2](../../guides/tiering.md#t2)) | The enforcement point that executes or mediates the action | Should not; correlation IDs link to it |
| Prompt and response logs and traces | [BAL-7.2](../../controls/control-catalog.md#bal-7-2) ([T1](../../guides/tiering.md#t1)); [BAL-7.10](../../controls/control-catalog.md#bal-7-10) ([T2](../../guides/tiering.md#t2)) | Application, platform, observability tool or vendor | Yes |
| AI security events and administrative changes | [BAL-7.3](../../controls/control-catalog.md#bal-7-3) ([T1](../../guides/tiering.md#t1)) | Guardrails, enforcement points, AI platforms | Summaries only |
| Policy decision records | [BAL-7.8](../../controls/control-catalog.md#bal-7-8) ([T2](../../guides/tiering.md#t2)) | Guardrails and policy enforcement points | References only |

[BAL-4.4](../../controls/control-catalog.md#bal-4-4) governs retention of AI content, including prompts, outputs, memory, embeddings and indexes. The shortest duration stipulated by [BAL-7.1](../../controls/control-catalog.md#bal-7-1) is a mandatory security-record condition. Any prompt or response content that is included in an action record adheres to [BAL-4.4](../../controls/control-catalog.md#bal-4-4) and is safeguarded by [BAL-7.2](../../controls/control-catalog.md#bal-7-2).

## Assumed baseline

Generic security-operations capabilities are presumed to originate from the organization's current security operations program and are not rephrased as Ballast controls. These encompass standard event schemas, signed webhooks, alert deduplication, severity routing, and response automation. Domain 7 specifies only the additional requirements introduced by AI. AI expenditure and usage alerting is [BAL-3.8](../../controls/control-catalog.md#bal-3-8), and AI security reporting to executives is [BAL-1.14](../../controls/control-catalog.md#bal-1-14).

Informative guidance: examples, standards and parameter defaults. The requirement text above is what an assessor tests.

| ID | Control | Notes |
|---|---|---|
| [BAL-7.1](../../controls/control-catalog.md#bal-7-1) | Agent action audit log | Suggested default: 180 days, or longer where law or contract requires; this is a Ballast baseline, not an [EU AI Act](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai) figure. METR's August 2026 investigation found spoofed tool calls in roughly 7% of evaluated transcripts (an evaluation setting, not a base rate), so model narratives are not evidence. Endpoint agents ship records off-device promptly. Redaction before write, customer-managed keys and tamper evidence are in [BAL-7.10](../../controls/control-catalog.md#bal-7-10) ([T2](../../guides/tiering.md#t2), informative). |

| [BAL-7.4](../../controls/control-catalog.md#bal-7-4) | AI incident response playbooks | Informative: [CoSAI AI Incident Response Framework](https://www.coalitionforsecureai.org/wp-content/uploads/2026/03/AI-Incident-Response-1.pdf) v1.0 (Oct 2025); [OWASP GenAI Incident Response Guide 1.0](https://genai.owasp.org/resource/genai-incident-response-guide-1-0/) (Jul 2025). [BAL-1.2](../../controls/control-catalog.md#bal-1-2) names the AI incident lead; [BAL-8.4](../../controls/control-catalog.md#bal-8-4) sets vendor notification terms; rollback uses [BAL-4.14](../../controls/control-catalog.md#bal-4-14) where implemented. | [BAL-7.5](../../controls/control-catalog.md#bal-7-5) | AI activity anomaly detection | An [A3](../../guides/tiering.md#a3) agent's declared envelope ([BAL-3.1](../../controls/control-catalog.md#bal-3-1)) is a ready-made profile; learned baselines suit high-volume integrations. Typical deviations: first use of a tool, a new destination domain, record volumes far above baseline, off-hours activity, or a third-party AI app's OAuth client exporting whole object tables (the Salesloft Drift pattern, 2025). | [BAL-7.6](../../controls/control-catalog.md#bal-7-6) | Data concentration detection | Example thresholds: more than 50 personal-data records, or more than 20 documents labeled restricted, per user or agent per hour. | [BAL-7.7](../../controls/control-catalog.md#bal-7-7) | Tool and MCP usage telemetry | Gateway, MCP proxy or platform logs are adequate sources. Suggested defaults: flag components unused for 90 days, and flag a tenfold change in call volume or response size or responses that reference new external domains. Remote MCP servers can change behavior without changing their definitions (ATLAS AML.T0109, rug pull), so usage signals add to the fingerprinting in [BAL-5.17](../../controls/control-catalog.md#bal-5-17). |
| [BAL-7.8](../../controls/control-catalog.md#bal-7-8) | Policy decision records | Most injection and leakage guardrails are classifiers with no rule to report, so record detector, version, score and threshold instead. Store references (hashes, record IDs) to evaluated inputs, not copies, so decision logs do not become an unprotected second prompt log. Decision records also feed guardrail efficacy measurement ([BAL-5.11](../../controls/control-catalog.md#bal-5-11)). [BAL-7.1](../../controls/control-catalog.md#bal-7-1) already sets the minimum decision fields for agent actions. |
| [BAL-7.9](../../controls/control-catalog.md#bal-7-9) | Investigation reconstruction | Suggested defaults: reconstruction within 4 hours for Critical and 1 business day for High assets; look-back matching the [BAL-7.1](../../controls/control-catalog.md#bal-7-1) retention where privacy rules allow. In July 2026, OpenAI took about a week to establish that its own evaluation agents caused the Hugging Face intrusion. |
| [BAL-7.10](../../controls/control-catalog.md#bal-7-10) | Hardened prompt log protection | Reversible tokenization keeps investigation possible ([BAL-7.9](../../controls/control-catalog.md#bal-7-9)) while removing raw sensitive values from routine log access. Redaction rules should cover the data classes defined under [BAL-4.1](../../controls/control-catalog.md#bal-4-1). |
| [BAL-7.11](../../controls/control-catalog.md#bal-7-11) | Agentic action provenance | Propagate trace IDs with [W3C Trace Context](https://www.w3.org/TR/trace-context/) or the [OpenTelemetry GenAI semantic conventions](https://github.com/open-telemetry/semantic-conventions-genai) across gateways, MCP servers and sub-agents. The tool-definition hash shows whether a tool changed between approval ([BAL-5.17](../../controls/control-catalog.md#bal-5-17)) and use. Recording untrusted context sources lets responders trace an action back to the injected document or email. Log token identifiers (for example the jti claim), not the tokens themselves. |
| [BAL-7.12](../../controls/control-catalog.md#bal-7-12) | AI attack-chain detection content | ATLAS 2026.09 IDs for the minimum set: AML.T0077, AML.T0086 (encoded data); AML.T0080.000 (memory writes); AML.T0103, AML.T0081 (bypass flags or unexpected parents, as in the s1ngularity/Nx attack of Aug 2025, which ran AI CLIs with permission checks disabled); AML.T0109 (definition change); AML.T0083, AML.T0098 (credential reads). Validate detections by replaying [BAL-5.3](../../controls/control-catalog.md#bal-5-3) and [BAL-5.4](../../controls/control-catalog.md#bal-5-4) test cases, and pin them to the ATLAS release. |
| [BAL-7.13](../../controls/control-catalog.md#bal-7-13) | AI honeypots and canary tokens | ATLAS AML.M0039 AI Honeypots (added in release 2026.09). Examples: a decoy API key in an agent-readable configuration file; a canary document in a retrieval index that normal queries do not match; a decoy high-value tool no legitimate task needs. Decoys grant no real access, and decoy tools are described so benign agents are not drawn to them. Unlike the [BAL-5.4](../../controls/control-catalog.md#bal-5-4) test canaries, these run in production. |
