# Domain 2: Agent Identity, Authentication & Lifecycle

**Objective:** Give every agent and AI integration a distinct, owned identity with short-lived, protected and revocable credentials, and keep the delegating user's identity and limits attached to every action an agent takes on that user's behalf.

## Why it matters

Agents act with real credentials. When they borrow a maker's or user's credentials, share service accounts, keep long-lived keys or lose track of the user they serve, one injected instruction or stolen token can act with privileges nobody intended, and the audit trail ends at a shared account instead of an accountable person. Credentials held by AI vendors and connectors carry the same risk. In August 2025, attackers used OAuth tokens held by Salesloft's Drift AI chat integration to export data from many customers' Salesforce instances (GTIG). In September 2026, Unit 42 read a vaulted token from an agent runtime's memory through its default shell tool and replayed it from outside. This domain treats every agent and AI integration as an identity that is owned, scoped, short-lived, attributable and revocable.

**Key risks addressed**

- [OWASP Top 10 for LLM Applications 2026](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/README.md): LLM03:2026 Excessive Agency; LLM02:2026 Sensitive Information Disclosure; LLM08:2026 Hidden Context Exposure
- [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/): ASI03 Identity & Privilege Abuse; ASI04 Agentic Supply Chain Vulnerabilities; ASI07 Insecure Inter-Agent Communication; ASI08 Cascading Failures; ASI10 Rogue Agents
- [MITRE ATLAS](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.09) (release 2026.09): AML.T0012 Valid Accounts; AML.T0055 Unsecured Credentials; AML.T0083 Credentials from AI Agent Configuration; AML.T0090 OS Credential Dumping; AML.T0091.000 Use Alternate Authentication Material: Application Access Token; AML.T0085 Data from AI Services; AML.T0132 Misconfigured or Publicly Exposed AI Services

Control-level references to OWASP, [MITRE ATLAS](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.09), [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) and [ISO/IEC 42001](https://www.iso.org/standard/42001): [Standards crosswalk](../../mappings/crosswalk.md#domain-2)

## Identity patterns and the controls that apply

Most agents combine several of these patterns. Apply the controls for every pattern present. Controls without a [Control Tier](../../guides/tiering.md#control-tiers) label are [T1](../../guides/tiering.md#t1). The control table gives the [Control Tier](../../guides/tiering.md#control-tiers) and scope of each control.

| Pattern | Example | Controls |
|---|---|---|
| Agent acts under its own identity | Scheduled triage agent; event-triggered workflow agent | [BAL-2.1](../../controls/control-catalog.md#bal-2-1), [BAL-2.2](../../controls/control-catalog.md#bal-2-2), [BAL-2.4](../../controls/control-catalog.md#bal-2-4); [BAL-2.9](../../controls/control-catalog.md#bal-2-9), [BAL-2.10](../../controls/control-catalog.md#bal-2-10) ([T2](../../guides/tiering.md#t2)); [BAL-2.13](../../controls/control-catalog.md#bal-2-13) ([T3](../../guides/tiering.md#t3)) |
| Agent acts for the invoking user | Assistant that sends mail as the user; coding agent working for a developer | [BAL-2.3](../../controls/control-catalog.md#bal-2-3), [BAL-2.4](../../controls/control-catalog.md#bal-2-4); [BAL-2.10](../../controls/control-catalog.md#bal-2-10) ([T2](../../guides/tiering.md#t2)); [BAL-2.13](../../controls/control-catalog.md#bal-2-13) ([T3](../../guides/tiering.md#t3)) |
| Agent delegates to other agents or services | Orchestrator with sub-agents | [BAL-2.3](../../controls/control-catalog.md#bal-2-3); [BAL-2.12](../../controls/control-catalog.md#bal-2-12) and [BAL-6.21](../../controls/control-catalog.md#bal-6-21) ([T2](../../guides/tiering.md#t2)) |
| An EXEC asset can reach credentials | Coding agent; code interpreter or filesystem-writing tool that calls APIs | [BAL-2.4](../../controls/control-catalog.md#bal-2-4), [BAL-6.13](../../controls/control-catalog.md#bal-6-13); [BAL-2.11](../../controls/control-catalog.md#bal-2-11) ([T2](../../guides/tiering.md#t2)) |
| Agent reaches tools through MCP | Remote MCP server; MCP client in an IDE or agent | [BAL-2.8](../../controls/control-catalog.md#bal-2-8), [BAL-2.4](../../controls/control-catalog.md#bal-2-4) |
| Third-party AI app holds grants to organizational data | Meeting notetaker; AI sales assistant | [BAL-2.6](../../controls/control-catalog.md#bal-2-6), [BAL-2.7](../../controls/control-catalog.md#bal-2-7) |
| People sign in to AI services | Chat assistant; AI coding tool | [BAL-2.5](../../controls/control-catalog.md#bal-2-5) |

Some assets carry none of the AGENT, EXT, EXEC, MULTI or INFRA tags. An example is a vendor-operated copilot that only answers within each user's own permissions. These assets have no asset-level controls in this domain. The Program controls [BAL-2.5](../../controls/control-catalog.md#bal-2-5) to [BAL-2.7](../../controls/control-catalog.md#bal-2-7) and Domain 8 cover their identity exposure.

## Implementation notes

Informative guidance: examples, standards and parameter defaults. The requirement text above is what an assessor tests.

| ID | Control | Notes |
|---|---|---|
| [BAL-2.1](../../controls/control-catalog.md#bal-2-1) | Scoped agent identity | An agent that acts only for its invoking user is assessed under [BAL-2.3](../../controls/control-catalog.md#bal-2-3). Prefer platform workload identity to static keys. Where a SaaS platform cannot issue a distinct agent principal, a dedicated least-privilege integration account per agent meets this control. A shared admin, shared integration or personal account does not, and needs a [BAL-1.13](../../controls/control-catalog.md#bal-1-13) exception. Replit (Jul 2025): after its agent deleted a production database, Replit separated development and production databases. |
| [BAL-2.2](../../controls/control-catalog.md#bal-2-2) | Sponsored agent identity lifecycle | Suggested defaults: certify quarterly for High or Critical assets and annually otherwise; reassign or disable within 5 business days of a sponsor's departure. The sponsor can be the asset's owner of record ([BAL-1.4](../../controls/control-catalog.md#bal-1-4)), and one joiner-mover-leaver process can serve both. Some platforms keep role bindings as inactive grants after an agent is deleted (Google Cloud agent identity documentation), so verify removal at the resource. Informative: [OWASP NHI Top 10](https://owasp.org/projects/non-human-identities-top-10) NHI1. |
| [BAL-2.3](../../controls/control-catalog.md#bal-2-3) | Attributable delegated actions | Examples: OAuth 2.0 token exchange ([RFC 8693](https://www.rfc-editor.org/info/rfc8693/)) or on-behalf-of flows. A user ID in a header or prompt is not verifiable. Suggested maximum lifetime: 1 hour. Prefer credentials issued specifically to the assistant. A single-user assistant may use its user's session only when it acts solely for that user, has no additional credentials, and its actions are identifiable in enforcement-point logs. Other credential and isolation controls still apply. Actions under the agent's own identity are attributed to its sponsor ([BAL-2.2](../../controls/control-catalog.md#bal-2-2)). Content from other users can still steer the agent ([BAL-3.5](../../controls/control-catalog.md#bal-3-5)). |
| [BAL-2.4](../../controls/control-catalog.md#bal-2-4) | Agent credential storage, lifetime and revocation | Suggested defaults: access tokens 1 hour or less; no non-expiring keys without a [BAL-1.13](../../controls/control-catalog.md#bal-1-13) exception; revocation within 15 minutes, matching the [BAL-3.7](../../controls/control-catalog.md#bal-3-7) halt objective. Shared Signals and CAEP events, or short token lifetimes, carry revocation to relying parties. The IETF AIMS draft (work in progress) calls static API keys an antipattern. Vaulting does not protect credentials in use (Unit 42, Sep 2026); see [BAL-6.13](../../controls/control-catalog.md#bal-6-13) and [BAL-2.11](../../controls/control-catalog.md#bal-2-11). |
| [BAL-2.5](../../controls/control-catalog.md#bal-2-5) | Enterprise identity plane for AI | For example SAML 2.0 or OpenID Connect with SCIM; suggested deprovisioning within 24 hours of departure. Disable local password sign-in where the service allows it. Confirm that deprovisioning also revokes API keys and tokens the leaver created on AI platforms ([BAL-1.8](../../controls/control-catalog.md#bal-1-8)). The MCP Enterprise-Managed Authorization extension, built on the IETF ID-JAG draft, lets the identity provider decide which AI clients may reach which MCP servers. |
| [BAL-2.6](../../controls/control-catalog.md#bal-2-6) | Third-party AI app consent governance | The Vercel incident (Apr 2026) originated with the compromise of Context.ai, a third-party AI tool used by an employee and connected as a Google Workspace OAuth app (Vercel bulletin). Identity providers rarely distinguish AI apps, so this usually means admin consent for all third-party apps, with AI apps routed through intake ([BAL-1.6](../../controls/control-catalog.md#bal-1-6)). Where self-consent cannot be disabled, [BAL-2.7](../../controls/control-catalog.md#bal-2-7) and [BAL-8.9](../../controls/control-catalog.md#bal-8-9) find the resulting grants. |
| [BAL-2.7](../../controls/control-catalog.md#bal-2-7) | Third-party AI grant inventory and revocation | In August 2025, attackers used OAuth tokens held by Salesloft's Drift AI chat integration to export data from customers' Salesforce instances, and used Drift Email tokens against Google Workspace (GTIG); Salesloft then revoked all tokens. Suggested defaults: recertify quarterly for High or Critical apps and annually otherwise; per-vendor revocation within 4 hours. Bulk export by these identities is detected under [BAL-7.5](../../controls/control-catalog.md#bal-7-5) where implemented. |
| [BAL-2.8](../../controls/control-catalog.md#bal-2-8) | MCP server authentication and token audience | [MCP specification 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization): servers publish Protected Resource Metadata ([RFC 9728](https://www.rfc-editor.org/info/rfc9728/)) and validate audience; clients send resource indicators ([RFC 8707](https://www.rfc-editor.org/info/rfc8707/)) and validate issuer ([RFC 9207](https://www.rfc-editor.org/info/rfc9207/)); token passthrough is forbidden. A May 2026 study found 40.55% of 7,973 remote MCP servers exposed tools without authentication (arXiv 2605.22333). GHSA-qx49-fqc8-xw99 (MCP Python SDK, Sep 2026) is why SDK changes trigger a re-check. Local servers: prefer stdio; bind HTTP servers to loopback and validate Origin ([BAL-6.16](../../controls/control-catalog.md#bal-6-16)). |
| [BAL-2.9](../../controls/control-catalog.md#bal-2-9) | Agent identity hygiene and misuse detection | Suggested defaults: 90 days unused or unexercised; remediation within 30 days. Human use of an agent identity breaks attribution ([OWASP NHI Top 10](https://owasp.org/projects/non-human-identities-top-10) NHI10, informative). Some low-code builders offer maker-provided credentials as a connection option. This control finds such connections serving other users; [BAL-1.11](../../controls/control-catalog.md#bal-1-11) is the preventive control. Grants held by third-party AI apps are recertified under [BAL-2.7](../../controls/control-catalog.md#bal-2-7). |
| [BAL-2.10](../../controls/control-catalog.md#bal-2-10) | No standing agent privilege | For example token exchange or workload identity federation that mints a credential per task, or rich authorization requests ([RFC 9396](https://www.rfc-editor.org/info/rfc9396/)) that describe the transaction. Suggested default: privileged credentials expire within 15 minutes. Once untrusted content is in context, an attacker can steer a model-written justification. [CoSAI Agentic IAM](https://www.coalitionforsecureai.org/wp-content/uploads/2026/04/agentic-identity-and-access-control.pdf) v1.0 (Mar 2026) recommends short-lived delegation tokens and zero standing privilege. Scope limits are [BAL-3.4](../../controls/control-catalog.md#bal-3-4). |
| [BAL-2.11](../../controls/control-catalog.md#bal-2-11) | Brokered agent credentials | Unit 42 (Sep 2026) read a vaulted service-account JWT from an AWS AgentCore Harness process's memory through its default shell tool, then replayed it from an outside laptop. Vaults protect credentials at rest and in transit, not in use. CI steps that expose secrets to agents as environment variables fail the same way. Typical patterns: an egress proxy or MCP gateway that adds authorization headers, or a sidecar token broker. Builds on [BAL-6.13](../../controls/control-catalog.md#bal-6-13). |
| [BAL-2.12](../../controls/control-catalog.md#bal-2-12) | Delegation attenuation and depth limit | [RFC 8693](https://www.rfc-editor.org/info/rfc8693/) treats nested actor claims as informational only for access decisions, so attenuation needs a fresh, narrowed token at each hop rather than a forwarded one. [CoSAI Agentic IAM](https://www.coalitionforsecureai.org/wp-content/uploads/2026/04/agentic-identity-and-access-control.pdf) v1.0 (Mar 2026) says scope must not expand across hops and recommends a maximum delegation depth. Suggested defaults: depth 3, fan-out 10. Agent-to-agent authentication is [BAL-6.21](../../controls/control-catalog.md#bal-6-21). Per-task runtime limits within one agent are [BAL-6.12](../../controls/control-catalog.md#bal-6-12). |
| [BAL-2.13](../../controls/control-catalog.md#bal-2-13) | Sender-constrained agent tokens | For example DPoP ([RFC 9449](https://www.rfc-editor.org/info/rfc9449/)) or certificate-bound tokens over mutual TLS ([RFC 8705](https://www.rfc-editor.org/info/rfc8705/)), with attested workload identity such as [SPIFFE](https://spiffe.io/) or the [IETF WIMSE](https://datatracker.ietf.org/group/wimse/about/) work. Keep the key non-exportable and outside model-directed execution ([BAL-2.11](../../controls/control-catalog.md#bal-2-11)). Binding stops off-host replay, not misuse inside a compromised runtime. If any action class operates at [A4](../../guides/tiering.md#a4), all access tokens used by that asset must meet [BAL-2.13](../../controls/control-catalog.md#bal-2-13). An unsupported connection must be fixed or removed before [A4](../../guides/tiering.md#a4) operation is allowed. The [A4](../../guides/tiering.md#a4) conditions cannot be tailored or risk-accepted. |
