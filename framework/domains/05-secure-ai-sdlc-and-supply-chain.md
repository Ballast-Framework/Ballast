# Domain 5: Secure AI SDLC & Supply Chain

**Objective:** Admit models, agent components and dependencies only from reviewed, pinned and verified sources, hold AI-written code to the same gates as human-written code, and put every AI asset the organization builds through change control and adversarial testing before release and on every change.

## Why it matters

AI assets are built from parts that ordinary software assurance misses: model files that can run code when loaded, MCP servers and skills whose behavior can change after approval, extensions and coding agents holding developer credentials, and package names that models invent. In September 2025 the postmark-mcp server began silently copying every email it sent to an attacker after about 15 clean releases. In February 2026 a prompt injection in a GitHub issue title, read by an AI triage workflow, started the chain that published a malicious Cline CLI release to npm. A one-time review at approval would have caught neither. This domain pins and re-reviews components, gates dependency intake, isolates agents that outsiders can trigger, and tests every model, prompt and tool change against a threat model before release.

**Key risks addressed**

- [OWASP Top 10 for LLM Applications 2026](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/README.md): LLM04:2026 Supply Chain; LLM05:2026 Data and Model Poisoning; LLM01:2026 Prompt Injection; LLM10:2026 Improper Output Handling
- [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/): ASI04 Agentic Supply Chain Vulnerabilities; ASI05 Unexpected Code Execution (RCE); ASI01 Agent Goal Hijack
- [MITRE ATLAS](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.09) (release 2026.09): AML.T0010 AI Supply Chain Compromise (sub-techniques .001 AI Software, .003 Model, .005 AI Agent Tool); AML.T0109 AI Supply Chain Rug Pull; AML.T0110 AI Agent Tool Poisoning; AML.T0011.000 User Execution: Unsafe AI Artifacts; AML.T0060 Publish Hallucinated Entities; AML.T0119 Exploit Automated Artifact Processing Pipeline

Control-level references to OWASP, [MITRE ATLAS](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.09), [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) and [ISO/IEC 42001](https://www.iso.org/standard/42001): [Standards crosswalk](../../mappings/crosswalk.md#domain-5)

## How the controls fit together

- **Building and changing AI assets (BUILT):** the threat model ([BAL-5.1](../../controls/control-catalog.md#bal-5-1)) defines what must be tested. Change management ([BAL-5.2](../../controls/control-catalog.md#bal-5-2)) decides when testing runs. Adversarial, indirect-injection and regression testing ([BAL-5.3](../../controls/control-catalog.md#bal-5-3) to [BAL-5.5](../../controls/control-catalog.md#bal-5-5)) produce the results, and the release gate ([BAL-5.6](../../controls/control-catalog.md#bal-5-6)) decides whether the asset ships. Principle 6 rests on this [T1](../../guides/tiering.md#t1) chain. At [T2](../../guides/tiering.md#t2), scheduled re-evaluation, multi-step agent testing, adaptive injection testing, drift detection and guardrail efficacy measurement ([BAL-5.7](../../controls/control-catalog.md#bal-5-7) to [BAL-5.11](../../controls/control-catalog.md#bal-5-11)) extend the same loop into operation. No [T1](../../guides/tiering.md#t1) control depends on them.
- **Model artifacts (MODEL):** at [T1](../../guides/tiering.md#t1), intake scanning, safe loading and integrity verification ([BAL-5.12](../../controls/control-catalog.md#bal-5-12) to [BAL-5.14](../../controls/control-catalog.md#bal-5-14)). At [T2](../../guides/tiering.md#t2), provenance and signing of models the organization produces ([BAL-5.15](../../controls/control-catalog.md#bal-5-15)). Scanning is defense in depth. Safe loading and immutable pinning are the primary controls.
- **Agent components and the coding toolchain (EXT, CODE):** at [T1](../../guides/tiering.md#t1), component review ([BAL-5.16](../../controls/control-catalog.md#bal-5-16)), pinning and re-approval ([BAL-5.17](../../controls/control-catalog.md#bal-5-17)), the approved catalog ([BAL-5.18](../../controls/control-catalog.md#bal-5-18)), coding-tool policy ([BAL-5.21](../../controls/control-catalog.md#bal-5-21)), governed dependency intake ([BAL-5.20](../../controls/control-catalog.md#bal-5-20)), security parity for AI-generated code ([BAL-5.22](../../controls/control-catalog.md#bal-5-22)) and CI/CD isolation for agents that outsiders can trigger ([BAL-5.23](../../controls/control-catalog.md#bal-5-23)). At [T2](../../guides/tiering.md#t2), extension update control ([BAL-5.19](../../controls/control-catalog.md#bal-5-19)).
- **Low-code agents** that the organization builds are BUILT. They pass the release gate through a documented pre-publish sign-off. **Vendor-operated SaaS AI features** are not BUILT. They enter through intake ([BAL-1.6](../../controls/control-catalog.md#bal-1-6)) and the vendor controls in Domain 8, not through this domain's release gate.

## Boundaries with other controls

- [BAL-5.17](../../controls/control-catalog.md#bal-5-17) decides which version of an agent component may run. [BAL-5.19](../../controls/control-catalog.md#bal-5-19) decides when an approved new version of an IDE or AI coding extension rolls out. Score each outcome once.
- Repository-supplied agent configuration (MCP configuration, hooks, rules and instruction files) and auto-approve modes are covered by [BAL-6.16](../../controls/control-catalog.md#bal-6-16). Coding-agent sandboxing, and keeping coding agents away from production and publishing credentials, are covered by [BAL-6.13](../../controls/control-catalog.md#bal-6-13).
- When an agent installs an unapproved dependency, extension or MCP server, or merges a change it authored, the action needs human approval under [BAL-3.6](../../controls/control-catalog.md#bal-3-6). Allowlist entries are keyed to the approved tool-definition fingerprint under [BAL-3.2](../../controls/control-catalog.md#bal-3-2).
- External reports of vulnerabilities in the organization's AI features are received under [BAL-7.4](../../controls/control-catalog.md#bal-7-4) and become regression cases under [BAL-5.5](../../controls/control-catalog.md#bal-5-5).
- External models are risk-assessed before ingestion under [BAL-8.1](../../controls/control-catalog.md#bal-8-1). Vendor model updates and retirements are monitored under [BAL-8.8](../../controls/control-catalog.md#bal-8-8) and handled as changes under [BAL-5.2](../../controls/control-catalog.md#bal-5-2).

## Implementation notes

Informative guidance: examples, standards and parameter defaults. The requirement text above is what an assessor tests.

| ID | Control | Notes |
|---|---|---|
| [BAL-5.1](../../controls/control-catalog.md#bal-5-1) | AI threat modeling | A data-flow diagram plus a source-to-sink table is enough. The [BAL-3.5](../../controls/control-catalog.md#bal-3-5) capability profile is a useful starting point. [ETSI EN 304 223](https://portal.etsi.org/webapp/WorkProgram/Report_WorkItem.asp?WKI_ID=74952) requires threat analysis (provision 5.1.3-1) and requires it to be repeated when settings or configuration change (5.1.3-1.1). ATLAS techniques and the OWASP Top 10 lists work as threat checklists. Treat rendered links and images as sinks, because they can carry data out ([BAL-6.3](../../controls/control-catalog.md#bal-6-3)). |
| [BAL-5.2](../../controls/control-catalog.md#bal-5-2) | AI change management | Treat provider notices of model updates, alias changes and retirements ([BAL-8.8](../../controls/control-catalog.md#bal-8-8)) as changes, and prefer dated snapshot IDs to aliases such as 'latest'. Suggested re-test period for unpinnable provider changes: 5 business days. Policy as code and automatic AI-BOM regeneration at each release are implementation options. Narrow fine-tuning can broadly degrade safety (Betley et al., Nature 2026), so treat fine-tunes and adapters like any other change. |
| [BAL-5.3](../../controls/control-catalog.md#bal-5-3) | Adversarial security test suite | Public test catalogs such as the OWASP AI Testing Guide and benchmarks such as AgentDojo and JailbreakBench are a starting point. Organization-specific cases use the asset's real tools, data classes and personas. Suggested review interval: every six months, and when a new attack class is published. Static suites overstate robustness. Adaptive testing is [BAL-5.9](../../controls/control-catalog.md#bal-5-9) ([T2](../../guides/tiering.md#t2)). |
| [BAL-5.4](../../controls/control-catalog.md#bal-5-4) | Indirect injection and exfiltration testing | Plant unique canary strings in data the asset can reach and watch for them at controlled endpoints. Include hidden text (white-on-white, Unicode tag characters, metadata, text in images) and instructions that trigger on a later turn. EchoLeak (Jun 2025, email) and ForcedLeak (Sep 2025, web form) show the pattern: outside content is retrieved as context, then data leaves through a rendered or fetched URL. |
| [BAL-5.5](../../controls/control-catalog.md#bal-5-5) | Regression testing on change | Keep the baseline separate from the adversarial suite so results stay comparable across versions. Suggested tolerance: no new failure in any security-critical case, and an aggregate drop of no more than about 2 percentage points. Valid reports received through the [BAL-7.4](../../controls/control-catalog.md#bal-7-4) external reporting channel become regression cases once fixed. |
| [BAL-5.6](../../controls/control-catalog.md#bal-5-6) | AI security release gate | Set thresholds per category: for example, zero failures for canary exfiltration and for tool-misuse cases that reach a high-impact sink, and a defined maximum attack success rate for each jailbreak family. Where [BAL-5.9](../../controls/control-catalog.md#bal-5-9) is implemented, its threshold also blocks release. Results go to the AI governance owner under [BAL-1.12](../../controls/control-catalog.md#bal-1-12). Exceptions follow [BAL-1.13](../../controls/control-catalog.md#bal-1-13). |
| [BAL-5.7](../../controls/control-catalog.md#bal-5-7) | Scheduled security re-evaluation | Suggested cadence: annually for High assets and quarterly for Critical assets. Unchanged assets still need re-testing, because new attack classes appear, provider-side safety layers change without a version change, and retrieved content shifts. Add newly published techniques to the suites before each scheduled run. |
| [BAL-5.8](../../controls/control-catalog.md#bal-5-8) | Multi-step agent testing | Run tests where tools and data are realistic but production writes are not possible. In the Replit incident (July 2025), an agent deleted a production database during a code freeze and misreported what it had done, so the agent's own report is not evidence. AgentDojo provides multi-step injection scenarios. |
| [BAL-5.9](../../controls/control-catalog.md#bal-5-9) | Adaptive prompt-injection testing | The Attacker Moves Second (Nasr, Carlini, Tramer et al., arXiv 2510.09023, Oct 2025) bypassed 12 published defenses, mostly with over 90% success, although most had originally reported near-zero attack success. Give testers the defense specification. State the budget explicitly, for example 500 adaptive attempts per input path, so results stay comparable over time. |
| [BAL-5.10](../../controls/control-catalog.md#bal-5-10) | Drift and degradation detection | Useful indicators include refusal rate, guardrail trigger rate, blocked-action rate, groundedness or hallucination score, and tool-call error rate. Drift often follows provider-side changes, shifts in retrieved content or prompt edits, so correlate alerts with [BAL-5.2](../../controls/control-catalog.md#bal-5-2) change records. Unexplained drift in behavior can also indicate poisoned training or retrieval data. |
| [BAL-5.11](../../controls/control-catalog.md#bal-5-11) | Guardrail efficacy measurement | Vendor-reported accuracy is not evidence. Measure on the asset's own traffic patterns, languages and formats, including obfuscated, encoded and multimodal attacks. Thresholds are organization-defined for each guardrail and use case. Detection is a tripwire, not a boundary ([BAL-6.1](../../controls/control-catalog.md#bal-6-1), [BAL-6.4](../../controls/control-catalog.md#bal-6-4)), so efficacy results drive tuning and alerting, not authorization decisions. |
| [BAL-5.12](../../controls/control-catalog.md#bal-5-12) | Model artifact intake scanning | Cover pickle-based, safetensors, ONNX, GGUF and framework-native formats. Scanning is defense in depth. JFrog disclosed three PickleScan bypasses (CVE-2025-10155, -10156 and -10157) in Dec 2025, and poisoned GGUF chat templates (AML.T0018.003) change behavior without touching weights. Pair scanning with [BAL-5.13](../../controls/control-catalog.md#bal-5-13) and [BAL-5.14](../../controls/control-catalog.md#bal-5-14). Risk assessment before ingestion is [BAL-8.1](../../controls/control-catalog.md#bal-8-1). |
| [BAL-5.13](../../controls/control-catalog.md#bal-5-13) | Safe model loading | For example, disable trust_remote_code and serve safetensors. Restricted loaders are not a boundary: CVE-2025-32434 allowed code execution in PyTorch before 2.6.0 even with weights_only=True. A common pattern is to convert a pickle checkpoint once, in a disposable job without secrets or network access, and keep only the converted output. |
| [BAL-5.14](../../controls/control-catalog.md#bal-5-14) | Model integrity verification | Unit 42 (Sep 2025) showed that re-registering deleted Hugging Face namespaces gave code execution in cloud model catalogs that referenced models by name. Revision pinning plus an internal mirror ([BAL-5.12](../../controls/control-catalog.md#bal-5-12)) prevents this. [CoSAI's Artifact Integrity Maturity Model](https://www.coalitionforsecureai.org/wp-content/uploads/2026/10/aimm-artifact-integrity-maturity-model.pdf) (Oct 2026) places consumer hash and signature verification at Level 1. Signing models the organization produces is [BAL-5.15](../../controls/control-catalog.md#bal-5-15) ([T2](../../guides/tiering.md#t2)). |
| [BAL-5.15](../../controls/control-catalog.md#bal-5-15) | Model provenance, lineage and signing | Record lineage in the format used for [BAL-1.7](../../controls/control-catalog.md#bal-1-7), for example a [CycloneDX ML-BOM](https://cyclonedx.org/capabilities/mlbom/) or the [SPDX 3.0 AI profile](https://spdx.github.io/spdx-spec/v3.0.1/). Signing can use any scheme the deployment platform verifies, such as Sigstore-based model signing. Organizations that distribute models externally should treat signing as baseline ([CoSAI Artifact Integrity Maturity Model](https://www.coalitionforsecureai.org/wp-content/uploads/2026/10/aimm-artifact-integrity-maturity-model.pdf), Level 1). API-only models need only the [BAL-1.7](../../controls/control-catalog.md#bal-1-7) minimum record. |
| [BAL-5.16](../../controls/control-catalog.md#bal-5-16) | Agent component security review | Koi Security found 341 malicious skills among 2,857 on ClawHub (Feb 2026); 335 of them used fake prerequisites to install an infostealer. Review tool descriptions as prompts, because they reach the model before any call. Behavioral review records network destinations, file access and spawned processes. Runtime capability classification is [BAL-3.3](../../controls/control-catalog.md#bal-3-3), and [BAL-5.17](../../controls/control-catalog.md#bal-5-17) binds trust to content. |
| [BAL-5.17](../../controls/control-catalog.md#bal-5-17) | Agent component pinning and re-approval | postmark-mcp shipped about 15 clean versions before 1.0.16 added a hidden BCC to every email (Sep 2025). MCPoison (CVE-2025-54136) bound approval to a server name, not its content. Running npx or uvx without a pinned version is unpinned execution. Disable agent self-update or route it through approval. Remote servers can change behavior without changing definitions, so egress control ([BAL-6.14](../../controls/control-catalog.md#bal-6-14)) and tool telemetry ([BAL-7.7](../../controls/control-catalog.md#bal-7-7), where implemented) compensate. |
| [BAL-5.18](../../controls/control-catalog.md#bal-5-18) | Approved AI component catalog | An internal registry or mirror is one way to implement this. Non-AI IDE extensions can enter through standard software approval. Suggested removal period: 24 hours for components withdrawn as malicious and 30 days otherwise. GlassWorm (Oct 2025) spread through Open VSX, a marketplace that several AI IDEs use. Where a tool cannot restrict install sources, detect installs through [BAL-1.9](../../controls/control-catalog.md#bal-1-9) and record a [BAL-1.13](../../controls/control-catalog.md#bal-1-13) exception. |
| [BAL-5.19](../../controls/control-catalog.md#bal-5-19) | AI coding extension update control | Amazon Q Developer for VS Code 1.84.0 (July 2025) was an official release from the verified publisher, yet it carried an injected wiper prompt after an over-scoped token was compromised. AWS says the code did not run, and 1.85.0 removed it (AWS-2025-015). Suggested delay: 7 days, with an expedited path for security fixes. [BAL-5.17](../../controls/control-catalog.md#bal-5-17) decides which version may run; this control decides when it rolls out. |
| [BAL-5.20](../../controls/control-catalog.md#bal-5-20) | Governed dependency intake | Suggested minimum age: 7 days. Malicious releases are often pulled within hours: LiteLLM 1.82.7 and 1.82.8 were quarantined by PyPI after about 40 minutes, although the LiteLLM advisory treats installs between 10:39 and 16:00 UTC as at risk (Mar 2026), and Cline CLI 2.3.0 was deprecated after about 8 hours (Feb 2026). Shai-Hulud 2.0 ran at pre-install (Nov 2025). The hallucinated name react-codeshift spread through agent skill files to 237+ repositories (Jan 2026). Agent-initiated installs also fall under [BAL-3.6](../../controls/control-catalog.md#bal-3-6). |
| [BAL-5.21](../../controls/control-catalog.md#bal-5-21) | Coding assistant and agent policy | Some coding tools let users switch to third-party models with different data terms. Limit them to models whose [BAL-8.7](../../controls/control-catalog.md#bal-8-7) profile permits the code's data classes. Typical exclusions cover secrets and key material, regulated data and security-sensitive code. Coding-agent sandboxing is [BAL-6.13](../../controls/control-catalog.md#bal-6-13) and configuration lockdown is [BAL-6.16](../../controls/control-catalog.md#bal-6-16). Detection of personal-license agents is [BAL-8.11](../../controls/control-catalog.md#bal-8-11) ([T2](../../guides/tiering.md#t2)). |
| [BAL-5.22](../../controls/control-catalog.md#bal-5-22) | AI-generated code security parity | Veracode's 2026 GenAI Code Security Report (Jul 2026) put the average security pass rate of AI-generated code at 56%, with no improvement on earlier years. Identify agent authorship with commit trailers, labels or dedicated agent identities. Merging agent-authored changes needs a human approver other than the invoker, and agents do not approve their own changes ([BAL-3.6](../../controls/control-catalog.md#bal-3-6)). |
| [BAL-5.23](../../controls/control-catalog.md#bal-5-23) | Isolation of event-triggered agents in CI/CD | In Clinejection (Feb 2026), a prompt injection in an issue title steered an AI triage workflow that any GitHub user could trigger. Actions cache poisoning then reached the nightly release workflow's publishing credentials, and a malicious cline 2.3.0 reached npm. Deliver agent proposals as comments or patches that a human applies. Maintainer-triggered agents that read outside content fall under [BAL-3.5](../../controls/control-catalog.md#bal-3-5) and [BAL-3.6](../../controls/control-catalog.md#bal-3-6). |

## Evidence examples

Examples of evidence an assessor can request. They are illustrative; any evidence that demonstrates the outcome is acceptable.

| ID | Control | Evidence examples |
|---|---|---|
| [BAL-5.1](../../controls/control-catalog.md#bal-5-1) | AI threat modeling | Threat model for a sampled asset with data-flow diagram, untrusted inputs, high-impact sinks and delegation chains; source-to-sink table naming the control and test for each path; revision history showing an update at the last [autonomy promotion](../../guides/tiering.md#autonomy-levels) or material change. |
| [BAL-5.2](../../controls/control-catalog.md#bal-5-2) | AI change management | Change records for the last three changes showing author, independent approver, impact assessment and linked test results; configuration showing pinned model versions or snapshots; AI bill of materials entry updated with the last model or tool change. |
| [BAL-5.3](../../controls/control-catalog.md#bal-5-3) | Adversarial security test suite | Test suite inventory listing attack families and case counts for a sampled asset; the last two run reports with pass and fail results; record of the last suite review, including organization-specific scenarios for a sampled High or Critical asset. |
| [BAL-5.4](../../controls/control-catalog.md#bal-5-4) | Indirect injection and exfiltration testing | Coverage matrix mapping each untrusted input path in the threat model to test cases; run report showing canary exfiltration attempts per path and their outcomes; test evidence that a session holding untrusted content could not trigger an unapproved external action. |
| [BAL-5.5](../../controls/control-catalog.md#bal-5-5) | Regression testing on change | Baseline scenario set with expected outcomes and change history, including cases added from defects; test logs showing the set ran for the last model and prompt change; the defined tolerance and any release blocked by a regression. |
| [BAL-5.6](../../controls/control-catalog.md#bal-5-6) | AI security release gate | Gate checklist or pipeline configuration with criteria and thresholds; release record for a sampled asset linking threat model, test results and approver; a release the gate blocked, or the pre-publish sign-off for a low-code agent. |
| [BAL-5.7](../../controls/control-catalog.md#bal-5-7) | Scheduled security re-evaluation | Re-evaluation schedule by risk rating; report of the last scheduled run for a sampled High or Critical asset; tracking records showing failures from that run remediated or risk-accepted within the defined timeline. |
| [BAL-5.8](../../controls/control-catalog.md#bal-5-8) | Multi-step agent testing | Multi-step test scenarios with expected end states in the target systems; run report showing system-of-record checks after each scenario; a case where the agent's reported outcome differed from the recorded state and how it was scored. |
| [BAL-5.9](../../controls/control-catalog.md#bal-5-9) | Adaptive prompt-injection testing | Adaptive test configuration stating attacker method and budget; results showing residual attack success rate per input path against the threshold; record that every relied-on guardrail was enabled in the tested configuration. |
| [BAL-5.10](../../controls/control-catalog.md#bal-5-10) | Drift and degradation detection | List of monitored indicators with baselines and thresholds; trend report for the last quarter; alert record for a threshold breach, or test evidence that a simulated breach raises an alert to the owner. |
| [BAL-5.11](../../controls/control-catalog.md#bal-5-11) | Guardrail efficacy measurement | Guardrail test set description with attack and benign sample counts; measurement report per guardrail showing detection and false-positive rates against thresholds; re-measurement record after the last guardrail, model or policy update. |
| [BAL-5.12](../../controls/control-catalog.md#bal-5-12) | Model artifact intake scanning | Registry or mirror configuration showing training and serving environments pull only from it; scan reports for the last three ingested models covering weights, tokenizer and template files; a quarantined or rejected artifact record. |
| [BAL-5.13](../../controls/control-catalog.md#bal-5-13) | Safe model loading | Loader and runtime configuration showing remote code execution disabled; inventory of production model formats; exception record and isolated job configuration (no credentials, no egress) for any code-executing load such as a format conversion. |
| [BAL-5.14](../../controls/control-catalog.md#bal-5-14) | Model integrity verification | Deployment manifests showing models pinned by revision hash or digest; verification step output from the last deployment; registry hash record for a sampled model, including tokenizer and chat-template files. |
| [BAL-5.15](../../controls/control-catalog.md#bal-5-15) | Model provenance, lineage and signing | Lineage record for a sampled fine-tuned model naming base model, source revision and dataset versions; signing step in the training or release pipeline; deployment log showing signature verification before the model was served. |
| [BAL-5.16](../../controls/control-catalog.md#bal-5-16) | Agent component security review | Review records showing approved instructions, dependencies and expected behavior, with checks for hidden instructions and unexpected data transfers; review records for the last three approved components and one rejected component; evidence that a new version or changed definition of an approved component triggered re-review before use. |
| [BAL-5.17](../../controls/control-catalog.md#bal-5-17) | Agent component pinning and re-approval | MCP client or gateway configuration showing pinned versions and content hashes; stored tool-definition fingerprints for approved servers; log or test showing a changed tool description blocked the server until re-approval. |
| [BAL-5.18](../../controls/control-catalog.md#bal-5-18) | Approved AI component catalog | Published catalog with approval dates and versions; managed-settings or policy export showing unsanctioned marketplaces and registries blocked; removal records for the last withdrawn component showing completion within the defined period. |
| [BAL-5.19](../../controls/control-catalog.md#bal-5-19) | AI coding extension update control | Managed update policy showing the delay or rollout rings; rollout records for the last two extension updates; approval record for a sampled extension listing the packs and dependencies it installs. |
| [BAL-5.20](../../controls/control-catalog.md#bal-5-20) | Governed dependency intake | Proxy or package-manager configuration for developer, agent and CI environments, including minimum-age and lifecycle-script settings; log of a blocked install of a too-new or known-malicious package; expedited-path record for the last urgent fix. |
| [BAL-5.21](../../controls/control-catalog.md#bal-5-21) | Coding assistant and agent policy | Approved coding tools and models list; admin console or managed-settings export showing model restrictions, content exclusions and logging enabled; [BAL-8.9](../../controls/control-catalog.md#bal-8-9) evidence showing personal and free-tier accounts restricted for coding tools. |
| [BAL-5.22](../../controls/control-catalog.md#bal-5-22) | AI-generated code security parity | Branch protection or ruleset export showing no bypass for agent or bot identities; pipeline configuration running secret scanning, SAST and SCA on every pull request; sample of agent-authored pull requests showing identification and scan results. |
| [BAL-5.23](../../controls/control-catalog.md#bal-5-23) | Isolation of event-triggered agents in CI/CD | Workflow definitions for agent jobs showing trigger events and token permissions; secret-scoping configuration showing release secrets unavailable to those jobs; runner and cache configuration separating agent jobs from release pipelines. |
